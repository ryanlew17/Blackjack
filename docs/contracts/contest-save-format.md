# contracts/contest-save-format — 竞赛模式存档格式 v1（S0 草案）

> 适用范围：竞赛模式元进度存档（难度解锁 + 图鉴状态）的负载契约草案；S3/S4 随实现定稿。经典模式存档见 [save-format.md](./save-format.md)，游戏负载与存储键独立；应用设置共享，见下文边界。
> 何时读取：实现竞赛存档、图鉴持久化或其导入导出时。
> 关联需求：无（S3/S4 实现时定稿字段）。
> 最后更新：2026-10-04
> 来源：2026-09-23 竞赛模式 S0 文档基线；2026-10-04 竞赛基线文档修订

## 定位与边界

- 竞赛模式对局**不持久化**：不存对局细节、战绩与历史；中断或刷新即放弃当前比赛（见 `../design/contest-rules.md` §8）。
- 只记录元进度：难度解锁状态、图鉴解锁与查看状态。不增加数字牌、道具手牌/留场效果、Match/Game/Round/Turn、搜索状态或规则预设字段；公开遭遇与场胜结果确定后提交相应元进度。
- 独立存储键 `green-room.contest.v1`；经典键 `green-room.blackjack.v1` 及其负载一字不动。语言/音量等应用设置仍存于经典信封，不迁移、不复制。
- 无历史版本迁移问题：首版即 v1，未知版本拒绝（与经典存档同一原则，不猜、不迁移）。

## 负载（草案字段）

| 字段                     | 含义                                                                                                                                                       |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| version                  | 1                                                                                                                                                          |
| savedAt                  | 可解析日期                                                                                                                                                 |
| revision                 | 唯一 ID（安全上下文 UUID，非安全上下文降级为时间戳+随机串，规则同经典 @req REQ-2026-008）                                                                  |
| highestClearedDifficulty | 已通关的最高难度（null / easy / standard / challenge / danger / nightmare）；可玩难度集与自定义对局解锁均由解锁链推导（噩梦通关 = 解锁自定义），不冗余存储 |
| codex                    | `{ [cardId]: { unlocked, viewed } }`；viewed ⊆ unlocked；cardId 须属于当前卡牌目录                                                                         |

负载远小于经典存档（预估 < 16 KiB），具体上限与拒绝规则随 S3 定稿。

## 校验（草案）

1. 字节数、JSON、version。
2. 难度枚举合法、highestClearedDifficulty 在解锁链内。
3. codex 的 cardId 属于卡牌目录、viewed ⇒ unlocked。
4. 全部通过才展示导入预览，确认后替换；失败保持现有进度。

元进度读写、损坏提示与跨标签版本检查复用底层存储工具，模式适配见 [ADR-004](../adr/ADR-004-contest-turns-and-shared-boundaries.md)。元进度冲突须阻止过期写入并提示载入最新元进度；载入/导入不从存档恢复或覆盖当前内存牌面，不把经典的对局恢复流程直接搬入竞赛。S3 定稿比赛进行中导入/冲突的交互与解锁更新策略。

图鉴 cardId 是稳定道具定义 ID，不是数字牌 ID 或运行中的实例 ID。卡池/概率调整不自动改变负载格式；删除/重命名定义或改变契约须重新评估版本与校验，不能静默猜测未知 ID。本文仍为未实现草案，本次不修改经典信封或存档版本。

## 导出导入（草案）

提供轻量导出/导入：单 JSON 文件（建议文件名 `green-room-contest-YYYY-MM-DD.json`），内容仅为上述元进度。

图鉴子负载的纯校验与更新已实现于 `src/domain/contest/codex/`，见 [数据快照](../design/codex-data.md)。当前只用于候选数据层验证；未实现本文件的完整信封、生产卡池白名单、存储或导入导出，不能视为 v1 存档已交付。字段与版本未在本次变更。
