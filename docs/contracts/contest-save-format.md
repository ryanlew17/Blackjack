# contracts/contest-save-format — 竞赛元进度存档v1草案

> 适用范围：难度解锁与图鉴元进度的负载草案，S3/S4随实现定稿。
> 当前已实现图鉴子负载API和道具目录；完整信封、存储及导入导出尚未接入。经典格式见[save-format.md](./save-format.md)。

## 定位与边界

- 对局不持久化：不存牌面、道具手牌／留场、Match／Game／Round／Turn、历史、战绩或搜索状态；中断／刷新即放弃。
- 只保存难度通关、图鉴解锁与查看。拟用独立键 `green-room.contest.v1`；经典键 `green-room.blackjack.v1`及其负载保持兼容，语言／音量等设置继续经经典信封共享，不复制。
- 首版拟为v1；未知版本明确拒绝，不按字段猜测版本或自动迁移。
- 技能资格从已解锁难度与该档场次数>0派生，无独立购买／升级存档。所选技能、剩余次数、Game发动许可、隐身待办／生成来源与真实随机均属内存对局。
- 技能介绍独立于道具遭遇三态，不将技能ID或数字／道具实例ID填入codex字段。

## 负载（草案字段）

| 字段                     | 含义                                                                                             |
| ------------------------ | ------------------------------------------------------------------------------------------------ |
| version                  | 1                                                                                                |
| savedAt                  | 可解析日期                                                                                       |
| revision                 | 唯一ID；安全上下文用UUID，非安全上下文按经典实现降级                                             |
| highestClearedDifficulty | null／easy／standard／challenge／danger／nightmare；可玩难度与自定义解锁由解锁链推导，不冗余存储 |
| codex                    | `{ [cardId]: { unlocked, viewed } }`；稳定道具定义ID，viewed ⇒ unlocked；执行准入另行判断        |

负载字节上限与拒绝规则在S3根据完整格式定稿，不继承经典对局字段。

## 校验与导入导出（草案）

1. 检查字节数、JSON、version、元数据及难度枚举。
2. 原子校验codex的已知定义ID与状态，不部分接纳。
3. 全部通过后展示预览，确认才替换；失败保持原元进度。
4. 导入／载入只处理元进度，不恢复或覆盖正在进行的内存牌面。

导出为单JSON文件，建议名 `green-room-contest-YYYY-MM-DD.json`。元进度冲突须阻止过期写入并提示载入最新值，写入失败不回滚牌面或积分；比赛进行中的导入／冲突交互与解锁合并策略随S3定稿。底层工具可复用，模式生命周期遵守[ADR-004](../adr/ADR-004-contest-turns-and-shared-boundaries.md)。

[图鉴数据层](../design/codex-data.md)仅提供子负载校验与更新，不能据此将任意完整JSON视为已验证存档。场胜结果和授权遭遇先由引擎确定，再按已实现的元进度策略提交。

## 定稿与扩展条件

| 触发条件                           | 原位维护要求                                                                                                                          |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| S3首次实现元进度信封／读写之前     | 在对应实现REQ内定稿键、字段、字节上限、校验错误、导入确认、冲突与失败策略；实现和校验测试与本契约一致后，将实际支持部分改为正式契约。 |
| S4图鉴集成、主动技介绍接入         | 核对解锁／查看语义及道具ID范围；技能介绍不自动增加负载，已实现部分不再保留“尚未接入”。                                                |
| 删除／重命名定义或改变可持久化语义 | 先登记实现REQ并评估格式版本与兼容策略；纯卡池数量／概率变化不自动升级元进度负载版本。                                                 |

Agent在接入相关能力时依据实际字段与消费者决定改写或扩展主题；未实现部分继续标识为草案，验收证据归对应REQ，不追加逐项实施历史。
