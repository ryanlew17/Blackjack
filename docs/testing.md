# 测试与验证门槛

> 适用范围：Agent实施测试、任务验收与发布验证时的通用标准。
> 需求特有的验收步骤、检查结果和未覆盖边界写入对应需求文档；本文件不追加任务记录。

## 1. 自动检查

| 时机                         | 必做检查                                                                                       |
| ---------------------------- | ---------------------------------------------------------------------------------------------- |
| 开发期间                     | 按需运行受影响测试或类型检查。                                                                 |
| 代码任务收尾                 | 一次 `npm test`、`npm run typecheck`、`npm run format`。                                       |
| 纯文档任务收尾               | `npm run format`，核对本地链接、Markdown围栏及差异。                                           |
| 构建配置、依赖或发布相关改动 | 收尾额外执行 `npm run build`。                                                                 |
| 发布前                       | `npm test`、`npm run typecheck`、`npm run format:check`、`npm run build`，并完成§2浏览器验收。 |

检查通过后，仅在新增改动、失败修复或仍有未解边界时复跑。专项实验不自动加入每次任务的门槛。

## 2. 浏览器验收

使用Playwright。UI行为改动在任务收尾做一次针对改动范围的单浏览器冒烟，开发服务器或preview均可；检查交互、实际绘制和控制台／页面错误。

发布前使用正常构建的生产产物，覆盖：

| 运行方式                            | 门槛                                                                                           |
| ----------------------------------- | ---------------------------------------------------------------------------------------------- |
| 生产preview                         | Chromium完整核心流程、WebKit代表性场景、Firefox基础流程。                                      |
| 干净目录解压发布包后 `file://` 打开 | 至少Chromium／WebKit其一取得正常渲染、零控制台／页面错误的证据。                               |
| 明文HTTP＋实际局域网IP              | 确认非安全上下文，验证渲染、完整对局、动画中刷新恢复、真实导出／导入往返，零控制台／页面错误。 |

核心回归覆盖完整对局、快速重复输入、取消／暂停／退出、经典存档与动画中刷新恢复、真实文件导入导出及非法导入保护、跨标签冲突；检查中英文、320px、键盘焦点与减少动态效果。具体玩法和本次新增功能的场景以对应需求的验收标准为准。

使用隔离存档／固定输入取得可断言结果；截图须核对实际画面。测试夹具与调试入口不得进入生产产物。

## 3. 测试与验收原则

- 规则测试注入固定牌序和随机源，经真实transition／应用接口验证结果、事件及副作用；不以直接修改状态替代命令执行。
- 仅声明实际完成的检查。环境阻塞不计通过；模拟事件、移动视口、自动化和人工实测分别说明，历史结果不替代当前验证。
- 完成实现、适用检查及自审且无待修复问题后，即通过验收并归档；额外外审或人工测试按用户安排。
- 将最终结论、关键证据与未覆盖边界合并写入需求文档；不在此重复逐项清单、执行过程、测试数量或发布历史。

## 4. 验证操作的归属

- 常规自动回归保留在源码旁的 `*.test.ts`；可复用专项代码放在 `scripts/validation/`，在脚本中说明用途、输入、运行方式和适用边界。
- 一次性调试脚本、截图、夹具和日志放在忽略的 `output/` 或临时目录；归纳必要证据后清理，不转存为另一份长期验收日志。
- 本文件只保留通用门槛和操作入口，需求特有步骤留在需求文档。

按需实验：[51卡供应／概率模型](../scripts/validation/contest_supply_model.py)，用于复现或调整历史设计基线；运行 `python3 scripts/validation/contest_supply_model.py`。参考环境为Python 3.15，结果输出JSON；该模型不验证后续54卡生成、主动技或真实对抗平衡。
