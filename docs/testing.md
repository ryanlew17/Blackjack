## 1. 自动检查

检查按三档节奏执行，任务期间不要求反复全量运行：

- **开发期间**：按需运行与改动相关的检查（如只跑受影响的测试文件、`npm run typecheck`）。
- **任务收尾一次**（标记需求完成前）：`npm test`、`npm run typecheck`、`npm run format`。`npm run build` 仅在构建配置、依赖或发布相关改动时运行；纯文档改动只运行 `npm run format`。
- **发布前**：完整运行下列四项，并补做 §2 浏览器验收。

```bash
npm test              # Vitest：当前587项（26文件；REQ-025后）
npm run typecheck     # 严格 TypeScript
npm run format:check  # Prettier（源码、docs、双语 README、AGENTS.md 等；启动脚本与 LICENSE 不在其列）
npm run build         # tsc -b + vite build → dist/
```

## 2. 浏览器验收（发布前；UI 改动收尾时冒烟）

规范：使用 Playwright CLI（未引入第二套测试框架），先 `npm run build` 以生产产物走查（`npm run preview`）；仅记录实际覆盖，环境阻塞不计为通过。完整矩阵与下述 `file://`、明文 http 场景在发布前统一执行；UI 行为改动的任务收尾只做一次针对改动范围的单浏览器冒烟（开发服务器或 preview 均可）。固定牌序存档夹具导入后抽牌顺序确定，金额可精确断言；截图与夹具位于 `output/playwright/`（已忽略，不属发布内容）。

## 3. 已知边界

- Firefox：基础 93 项有成功证据；另有 7 项增补场景（分牌后加倍、存储禁用、页面恢复可见）因本机 Firefox 启动间歇性失败（`Could not find profile folder`）未取得通过证据，环境稳定后可补验。390px 视觉截图仅在 Chrome/WebKit 覆盖。
- 导入路径以 Playwright `setInputFiles` 驱动（等价真实文件选择）；导出经真实下载事件捕获文件内容验证，未验证浏览器另存对话框本身。
- 兼容性使用桌面浏览器及移动视口验证，未使用真实 iOS / Android 设备。
- 音效调用与静音偏好已验证；没有使用录音设备进行听感验收。
- 自动保存依赖浏览器站点数据；存储不可用时需要手动导出文件。当前为单机、虚拟筹码，无云端功能。
- `start-game.bat`（Windows）尚未在真实 Windows 机器上实测；`start-game.command` 已在 macOS 实测。
