## 背景

S1 界面只支持数字牌。S2 需要让玩家理解资源、连续用卡、目标与积分修正，并通过真实交互使用首批道具。本项将正式卡池和协调 API 一起接入首页的固定标准竞赛入口。

## 方案要点

- 正常入口切为标准 BO5 含道具开发预设，同步首页、规则、比分栏及结果的双语说明，去除无道具描述；两份 README 仅按实际产品行为同步。
- 展示自己道具手牌、对手公开数量、双方最多五项留场效果记录、当前目标和公开积分修正。对手未公开身份不进入 DOM、可访问名称、data 属性或选卡提示。
- 选择卡片→查看效果／合法条件→按需选择目标与弃牌费用→明确使用；取消／Esc 不消耗资源并恢复焦点。无选择参数的卡可采用简洁直接交互，不对每张卡增加多余确认。
- 合法性与可选目标由应用／引擎提供；指定抽取不预告真实成功，清除“最近”与选定目标的卡意不可混淆。提交前再经引擎验证；界面不自算积分与效果。
- 用卡回放结束后若仍轮到自己，可继续选卡或 Hit／Stay；展示失败但已消费、满手／合法零领取、目标替换、补给、计分来源和清理等定稿反馈。
- 维持短视口主操作可达：常规2–3张数字牌、收拢道具区时，784×803／320×900可见行动状态和 Hit／Stay；展开长手牌允许滚动，不能遮住焦点或弹层。保留主操作49px高度、键盘操作与减少动态设置。
- 返回／重开／弹层暂停与比赛完成后的直接新开豁免沿用现行语义；刷新丢弃比赛，经典保存继续正常。

### REQ-021 定稿输入（2026-10-21）

按[51卡表](../archive/REQ-2026-021-contest-trump-rule-contract.md#a-51卡规则限量与概率)渲染已准入卡，数量资格仅依所选难度列。显示逻辑暗牌的公开倍率／已揭示状态、共生待结算提示、从众记录／到期与短效封锁的确切Turn；不能把共生未来总和或双效暗牌实际增量提前透给未知方。窥序片段只显示给合法接收方，位置过期不继续标作当前堆顶；费用弃牌身份不写入对手DOM。0分护身仍展示完整已结算Round。

需要选择自己费用、公开明牌或可转移留场时提供合法目标，不开放查询隐藏库存。54个规划定义的名称／说明进入两字典，025的53张准入先接可玩反馈，回仙效果及技能关联在027完成；标准列自然未生成的卡用隔离夹具覆盖，不加生产调试入口。

### 2026-10-21 新术语与三卡界面

明确抽取／生成／删除／转移的反馈：出卡即销毁，留场展示持续效果而非可回收卡体。悔牌只提供022定义、023已实现的上一手撤销窗口，不暗示能倒退积分、随机或已知信息；赌命显示当前Game“下一次决胜Round决定局胜”的公开状态，平局继续而非误报赢整场。无需为极端库存抽尽增加弹层、回收按钮或替代玩法。

复用023观察契约：faceUpCardIds排除逻辑暗牌，即使已揭示也不可作为退换／绑定目标；value是原值，visibleTotal／total和已结算结果由引擎提供，不在UI重新相加判胜。窥序peek与privateCards仅给授权本人，过期位置不继续显示为当前堆顶。

027另接战前技能选择、独立球形按钮、隐身次数与反应窗口；本项不先造另一套技能临时UI。未准入回仙不能出现在本阶段真实库存中；027启用后复用现有选卡和反馈入口。53卡过渡及54卡最终状态分别记录，不以卡名文案已存在代表运行卡已完成。

## 验收标准

- [ ] 真实浏览器从首页进入含道具比赛，完成取牌、用卡、连续组合、Hit／Stay交权、回合计分与继续，生产入口无调试注入依赖。
- [ ] 需要选择的目标／费用可鼠标、触屏仿真及键盘完成；取消、Esc、状态变化和重复点击不误用卡、不重复消费。
- [ ] 对方隐藏手牌、隐藏成本身份及数字暗牌无DOM／可访问名称泄漏；揭示只发生于公开事件。
- [ ] 英文／中文、784×803与320×900、减少动态均有一次针对性浏览器走查，截图核对布局、49px主操作、无横向溢出与焦点可达；记录实际控制台结果。
- [ ] 覆盖补给零领取／手满、混合失败、替换／清除目标、攻防积分结果；难稳定自然抽到的场景可用隔离夹具验证，夹具不得进入生产入口。
- [ ] 暂停／取消／重开／刷新弃赛及经典刷新恢复回归通过；任务收尾检查，更新UI／规则快照和双语README，实际证据归入本需求。
