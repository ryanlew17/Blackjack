## 背景

候选数据、S1 原型和正式执行器必须在这里收敛成唯一生产可用的卡池与配置。只有逐卡通过规则与联动验证，才允许进入正常竞赛的抽取／明确生成渠道；应用必须支持同一行动方多次用卡的回放和中断。

## 方案要点

- 建立已准入定义和 S2 开发预设的明确入口；逐卡记录定义 ID、效果／费用、生成资格、测试位置、反制／联动证据。保留REQ-021原版台账中未准入项的身份，避免把候选与生产定义维护成两套可漂移的执行真相。
- 满足REQ-021的51卡／44组机制及022追加三卡的设计范围，按表中实施归属逐一验收；S3正式五档对抗预设不得用供应模拟或开发值冒充。
- 应用能够以已冻结标准 BO5 开发配置新开含道具比赛，对玩家开放结构化 PlayTrump（含必要目标／成本），权威状态仍由 controller 私有持有。下一项 UI 完成前正常页面保持完整的无道具流程，不能只发资源却没有使用入口。
- AI 此时仍用 baselinePolicy，不主动 PlayTrump；双方真实多卡行为通过受控端口／固定夹具驱动，不提前落地搜索。
- 每次命令先提交终态、再回放投影事件；合法用卡完成后恢复原行动方决策。退出、重开、暂停、跳过、可见性变化使旧回调失效；被取消的输入目标不在恢复后自动提交。
- 精确扩展生产依赖守卫，只准入本阶段实现的模块；不得将 prototype、testHelpers 或整份 experimental 通过通配放行。
- 全部 Storage 方法及 length 的零调用断言保留；S3 元进度承接仍留在 roadmap，S2 不提前放宽。

### REQ-021 定稿输入（2026-10-21）

逐卡登记[51卡表](../archive/REQ-2026-021-contest-trump-rule-contract.md#a-51卡规则限量与概率)全部定义的执行、数量、双语键与确定性测试；合计新增33个ID、保留原21个ID；原创provenance按实际设计来源登记REQ-021／022，扩展类型与校验，不伪填外部来源。earliestDifficulty已在021从候选类型和21条预设删除，本项扩展数据时不得重加；五档副本列是唯一生成资格。仅通过执行器／逐卡验证后才设生产准入，旧F1/P0与prototype继续隔离。

标准配置使用标准列，强效卡库存单副本上限覆盖从众等定向检索，不阻止明确生成或转入；高档专用定义用隔离夹具做真实引擎验收，正式难度页仍在S3。共生／倍率／提前揭示／私有窥序／隐蔽费用必须在完整载荷和逐帧观察中验证。设计已纳入的卡不得以“原E标签”或“最早难度”跳过；发现规则缺陷需回写021与相关REQ后再收敛实现。

### 2026-10-21 54卡登记与分阶段准入

以[022](../archive/REQ-2026-022-contest-trump-resources.md)追加表登记regret／skill-revival／sudden-death及新总量39/61/73/76/78，目录共有54定义。025完成53张可执行卡准入，回仙在027与主动技一并完成第54卡；未准入时明确排除该库存实例，不谎称过渡卡池总量等于最终54卡配置（危险／噩梦各少1，标准不受影响）。026先接53卡页面；027补回仙及技能页面后，028才最终验收组合对抗。

所有出卡体即时销毁，table仅是效果记录；旧discarded／prototype实例不可重新进入手牌／库存。生成、删除、转入是正式语义而非随机调试口，能获得哪些定义由冻结配置和准入集合决定；普通库存抽取保持每实例等概率，无earliestDifficulty。

主动技选择／球形按钮属于027，本项基线AI不自动用卡或技能。纯TS与生产依赖守卫只放行经过本批实际准入的定义；新三卡的来源登记为项目设计，不伪造原版来源。

## 验收标准

- [ ] 逐卡准入表列出REQ-021的51原定义＋悔牌／赌命共53卡的实现与测试位置；回仙第54卡定义已登记、执行及准入由027完成，不能混记完成数；生产只能取得已准入定义，双方同一预设可复现。
- [ ] 以实际定义与真实引擎验证连续用卡、满桌、失败消费、目标替换、混合与积分反制、资源耗尽；回合／局／场完整推进，无测试 marker 入生产。
- [ ] controller 验证玩家多卡→Hit/Stay、受控对方多卡→重决策，busy/paused/非行动方输入零副作用；基线AI仍不主动用卡。
- [ ] 用卡与领取回放各阶段暂停／恢复／退出／重开及强制旧回调覆盖，终态不回滚、不重复消费、无人操作时不会永久busy。
- [ ] Match 全程无存储调用、经典状态不变；生产入口守卫、观察隔离、任务收尾及纯度检查通过。
- [ ] REQ-023/024 的两项 S1 承接结论逐卡复核；更新卡池／架构／规则快照，记录 S3 待平衡参数。
