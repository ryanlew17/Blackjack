# REQ-2026-025: S2 首批卡池准入与应用接线

状态: done
来源: 用户（2026-10-21：从 S2 提炼 active 需求，最终落地道具机制与 AI 对抗）
关联设计: [竞赛规则](../../design/contest-rules.md) · [ADR-004](../../adr/ADR-004-contest-turns-and-shared-boundaries.md) · [S2 排期](../../roadmap.md#s2-需求拆分与实施顺序2026-10-21)
影响模块: src/domain/contest/trumps/、presets/、src/application/contest/、生产入口架构测试
前置依赖: REQ-021–024 验收完成；REQ-026 接可玩界面，REQ-027接主动技，REQ-028最后接组合AI。
非目标: 不启用五档难度页、图鉴／元进度、自定义或正式 AI；测试原型与实验全目录继续隔离。

## 背景

候选数据、S1 原型和正式执行器必须在这里收敛成唯一生产可用的卡池与配置。只有逐卡通过规则与联动验证，才允许进入正常竞赛的抽取／明确生成渠道；应用必须支持同一行动方多次用卡的回放和中断。

## 方案要点

- 建立已准入定义和 S2 开发预设的明确入口；逐卡记录定义 ID、效果／费用、生成资格、测试位置、反制／联动证据。保留REQ-021原版台账中未准入项的身份，避免把候选与生产定义维护成两套可漂移的执行真相。
- 满足REQ-021的51卡／44组机制及022追加三卡的设计范围，按表中实施归属逐一验收；S3正式五档对抗预设不得用供应模拟或开发值冒充。
- 应用能够以已冻结标准 BO5 开发配置新开含道具比赛，对玩家开放结构化 PlayTrump（含必要目标／成本），权威状态仍由 controller 私有持有。下一项 UI 完成前正常页面保持完整的无道具流程，不能只发资源却没有使用入口。
- AI 此时仍用 baselinePolicy，不主动 PlayTrump；双方真实多卡行为通过受控端口／固定夹具驱动，不提前落地搜索。
- 每次命令先提交终态、再回放投影事件；合法用卡完成后恢复原行动方决策。退出、重开、暂停、跳过、可见性变化使旧回调失效；被取消的输入目标不在恢复后自动提交。
- 精确扩展生产依赖守卫，只准入本阶段实现的模块；不得将 prototype、testHelpers 或整份 experimental 通过通配放行。
- 全部 Storage 方法及 length 的零调用断言保留；S3 元进度承接仍留在 roadmap，S2 不提前放宽。

含道具的默认随机源惰性建立三条独立推进的Mulberry32流，播种只取一次环境随机的三个种子；闲置或非法初始化不播种。显式注入仍用numbers／trumpGate／trumpSelection端口。额外消耗资源流不会移动数字游标，不把三个Math.random别名误认作独立流；搜索随机仍由028另接。
