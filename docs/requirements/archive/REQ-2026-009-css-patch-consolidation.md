影响模块: src/presentation/styles.css;文档回写 docs/design/ui.md

## 背景

项目经多轮 agent 交替迭代,styles.css 留下多处成对"旧值—新值"覆盖:后声明生效,前者为死代码。维护时极易只改前者导致"改了不生效",或误读当前实际值。已知清单(行号为 2026-09-22 审查时点):

- `.felt-table` 高度四组覆盖:494(约 205 行)→ 550(约 1499 行);`@media (min-width:1500px)` 530(约 986 行)→ 580(约 1503 行);`@media (max-width:760px)` 484(约 1076 行)→ 540(约 1509 行);`@media (max-width:420px)` 454(约 1213 行)→ 530(约 1513 行)。
- `@media (max-width:760px)` 拆为三个独立块(约 1030、1388、1458 行),同类选择器跨块覆盖(如 `.eyebrow` 字号、`.table-meta` 字号、`.split-hands` 覆盖 `.hand-zone` 的 left/right 6%→4%)。
- `.play-actions button` min-width 165px(约 683 行)→ 115px(约 1444 行),后块另补 `flex-wrap`。

## 方案要点

- 重构前先采集基准:Playwright 截图矩阵(320 / 390 / 760 / 1280 / 1600 视口 × 中英 × 关键状态:下注、玩家回合、结算、分牌、弹层打开)与各视口 `scrollWidth` 记录。
- 计算每个断点的最终生效值,将样式重写为单一规则集(基础规则 + 每断点一个块),删除全部被覆盖的死值;保持层叠结果严格等价。
- docs/design/ui.md §3 硬约定新增一条:**同一属性的多次补丁只保留最终值,禁止叠加旧值**(约束后续所有迭代)。

## 验收标准

- 重构前后截图矩阵逐项零像素差异,各视口 scrollWidth 记录一致。
- 代码走查:styles.css 不再存在同选择器同属性的成对覆盖;每个媒体断点只有一个规则块。
- `npm test`、`npm run typecheck`、`npm run format:check`、`npm run build` 全绿;ui.md 硬约定已回写。
