## 背景

在 S2 道具框架开发前将现有 21 张候选卡资料落为完整可查询的数据模块，并建立图鉴进度的数据操作边界。图鉴界面及持久化接线仍属后续里程碑。

## 方案要点

- 独立卡片 ID、结构化效果／条件／费用／生命周期、研究来源、双语名称与说明、五档库存和最低出现难度。
- 所有卡仍为实验候选，数据存在不等于正式准入；F1/P0 实验参数与定义分离，不实现其游戏算法。
- 完成图鉴查询、三态、公开遭遇更新、查看更新、未查看定位及数据校验；只操作纯数据，不接浏览器或对局。
- 难度入池不自动解锁图鉴；隐藏对手领取无身份字段，自定义不新增解锁；稳定定义 ID 与运行实例分离。
- 保留 S3 存档信封/存储和 S4 页面集成边界；开发数据目录不能直接当成正式存档卡片白名单。

## 验收标准

以下标准已通过开发者自审及用户验收。

- [x] 21 个唯一 ID，与研究目录一一对应；逐卡数据、五档数量及双语文案完整。
- [x] 即效／留场／混合可表达，类型无任意字符串公式；定义与预设只读。
- [x] 三态、重复遭遇幂等、查看保护、隐藏领取、自定义限制、未知 ID 和无效数据均有验证。
- [x] 查询不向未解锁条目暴露名称／效果；保留稳定排序和最前未查看条目。
- [x] 仅候选数据和图鉴数据操作，无玩法／AI 算法、存储接线或页面开发。
- [x] 测试、类型、格式通过，完成自审。
