## 在研主线：竞赛模式（v0.2.0 线）

### 背景与裁定

新增**竞赛模式**：参考《生化危机7》21 点的交替行动与道具联动，改编为积分制 BO-N 对弈。竞赛采用独立状态机与独立元进度存档，最小工具按实际消费者共享；当前决策见 [ADR-004](./adr/ADR-004-contest-turns-and-shared-boundaries.md)，[ADR-003](./adr/ADR-003-contest-mode-engine.md) 保留为部分被取代的历史。规则基线见 [contest-rules.md](./design/contest-rules.md)，元进度草案见 [contest-save-format.md](./contracts/contest-save-format.md)。S0 为文档阶段；REQ-012/013 前置文件架构与图鉴数据已验收归档，S1–S5 的完整玩法与页面尚未交付，当前可玩功能仍为经典模式。

局域网双人、线上部署、账号/云存档继续为 PRD 非目标（见 [prd.md](./prd.md) §3）。多副牌候选仍退役，竞赛采用唯一数字牌，不再承诺由双牌组卡承载多副体验。

### 设计基线摘要

- **四层单位**：Match（BO-N）→ Game（先得 5、平分递延目标）→ Round（一次发牌对弈与结算）→ Turn（一方连续用卡后要牌/停牌）。局结束清空道具手牌；回合结束清理留场效果，手牌可保留。
- **数字牌与判胜**：每 Round 重建共享的 1–11 各一张牌堆；各发两张，第一张对对手隐藏。默认牌面目标 21，目标可变，爆牌可挽救；双方爆牌则更接近目标者胜，同点数平局。无天然 Blackjack 优先级。
- **交替行动**：开场抛硬币定先手，逐 Round 轮换；双方主动决策，无 S17 庄家。用卡不换人，可连续联动；Hit/Stay 结束 Turn。停牌不是永久锁定，双方连续安静停牌才揭牌结算。
- **积分改编**：无道具修正时赢家 +1、平局 +0；目标递延不等于必须领先两分。计分道具方向、叠加与上下限在 S2 定稿，不直接复制原版损伤赌注。保险卡、双牌组卡退出基线，加倍只保留为候选映射。
- **道具系统**：获取与数字牌堆分离，取得后持有，使用时执行即效/留场/混合效果；五张留场容量、互斥目标与清除规则见设计。取消固定概率公式与容量初值承诺，S2 定模型、S3 定预设；不以一张用卡上限处理连锁终止。
- **AI 排期**：S1、S2 各自把 AI 需求放在最后实施。此前用确定的经典式占位策略：自身数字总和 <17 且可 Hit 则 Hit，否则 Stay，不主动使用道具。S1 末项固化无道具基线与信息隔离；S2 末项才实现可见信息推断、动态评价和有限多卡搜索，所有难度共用策略/预算，真实随机与搜索随机分离。
- **难度与图鉴**：保留 BO3/BO5/BO7/BO9、五档解锁链与公开遭遇即解锁图鉴。资源/容量/卡池数值等待验证，Match 内冻结配置；自定义只用已解锁/已选卡，不解锁新图鉴。
- **存档与版本**：只持久化难度与图鉴元进度，不存对局/战绩/历史；返回首页或刷新放弃内存比赛。应用设置共享，模式游戏负载与存储键独立。竞赛首个发布仍为 **v0.2.0**，经典规则与存档保持 v2。

## 流程

新需求先登记到 GitHub Issue 或 `requirements/active/REQ-*.md`，再在本路线图关联排期，不在 PRD 内写需求正文。落地后回写对应 `design/` 快照，按需求索引流程归档；发布后更新本表状态。未来存在同主题 GitHub Issue 时按 Issue 优先原则对齐。

版本迭代：自 v0.1.0（2026-09-22 首次发布）起，每次发布自动递增版本号，需求随所属发布迭代版本；仅当某一需求被标记重大升级时，由用户指定版本号跳跃。**竞赛模式线从 v0.2.0 起跳**：竞赛开发期间，经典模式的修复照常以 v0.1.x 递增发布；竞赛线内部迭代走 v0.2.x；0.x 语义下不占用 1.0.0，1.0.0 留待产品形态稳定后另行裁定。

v0.1.1（2026-09-22）为发布后紧急热修复（双击 `file://` 白屏，见 [ADR-002](./adr/ADR-002-singlefile-release-build.md)），只改构建产物形态，不改规则与存档。
