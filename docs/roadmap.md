### 技术实施顺序

- **共用模型先行**：保持四层边界与纯规则引擎，为 `legalActions` 接入规则参数；扩展保险阶段、当前手、逐手状态与结果、保险结果和每局汇总历史。具体拟议接口与验收写在 REQ-003。
- **多手能力落地**：先实现最多两手的分牌和统一庄家回合，再增加保险决策对开局天然检查的前置拦截，最后接入晚投降及完整组合验证。
- **贯穿存档与表现层**：每个阶段同步覆盖权威状态持久化、事件快照、导入校验、中英文文案与小屏操作；动画不决定赔付。保险允许半筹码，主注仍为整筹码。
- **统一发布**：当前工作区架构、设计及存档契约已回写 v2；需求须在最终验收通过后才归档。已有 REQ-001、REQ-002 保留原状态，不混入本次文档分支。

验收遵循 [测试门槛](./testing.md)：单元测试、类型、格式、构建，以及发布前中英文、320px、键盘操作、动画中恢复和跨标签冲突走查。仅记录实际浏览器覆盖；环境阻塞的引擎不计为通过（Firefox 基础 93 项已通过，额外 7 项补跑仍有环境阻塞，详见验收报告）。

## 未排期候选

以下方向仍未承诺交付顺序或日期，不属于规则 v2 范围。

| 方向                       | 说明                                                     | 备注                                                                                                                                                                             |
| -------------------------- | -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **局域网双人同玩**         | 同一局域网内两台设备同桌对玩（如轮流坐庄或共同对抗庄家） | 当前为纯前端单机架构，需引入轻量本地服务/信令与状态同步协议；规则引擎逐调用传参的设计（ADR-001）与先提交后渲染的数据流为同步奠定了基础，但仍属独立架构扩展，立项前需先出设计文档 |
| 多副牌                     | 2+ 副牌靴                                                | 改变牌张身份编码与存档 52 张覆盖校验，需升版本                                                                                                                                   |
| 线上部署                   | 发布静态站点                                             | 产物即 `dist/`，无服务端依赖                                                                                                                                                     |
| 账号 / 云存档 / 跨设备同步 | 作为独立架构扩展评估                                     | 与 local-first 定位冲突，需重新评审 PRD 非目标                                                                                                                                   |

## 流程

新需求先登记到 GitHub Issue 或 `requirements/active/REQ-*.md`，再在本路线图关联排期，不在 PRD 内写需求正文。落地后回写对应 `design/` 快照，按需求索引流程归档；发布后更新本表状态。未来存在同主题 GitHub Issue 时按 Issue 优先原则对齐。
