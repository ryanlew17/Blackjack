## 在研主线：竞赛模式（v0.2.0 线）

### 背景与裁定

新增**竞赛模式**：积分制 BO-N 对弈 + 道具卡的 roguelike 玩法，灵感来自《生化危机7》的 21 点。竞赛模式使用全新独立引擎与全新独立存档系统（[ADR-003](./adr/ADR-003-contest-mode-engine.md)），两模式能共用的算法沉淀入共用库（共用 / 经典 / 竞赛三库结构）。设计口径基线见 [design/contest-rules.md](./design/contest-rules.md)（S0 基线，未实现），存档契约草案见 [contracts/contest-save-format.md](./contracts/contest-save-format.md)。

原"未排期候选"清单随本次裁定整体退役：局域网双人、线上部署、账号/云存档升级为 PRD 非目标（见 [prd.md](./prd.md) §3）；多副牌候选一并移除——不升级为非目标，多副体验由竞赛模式双牌组卡承载（contest-rules §4.4）。

### 设计基线摘要

- **层级与赛制**：场（大比分，BO-N：轻松 BO3 / 标准·挑战 BO5 / 危险 BO7 / 噩梦 BO9，先赢多数局（过半）即"通关"）→ 局（小比分，所有难度统一先得 5 分，平分递延目标制：4:4→先得 7、6:6→先得 9，以此类推）→ 回合（一回合 21 点：双方停牌比点数，赢 +1 分、输则对方 +1 分）。BO-N 指大比分（场）。局结束清空双方道具手牌并重建牌靴，相当于重新游戏。
- **坐庄与 AI**：开局抛硬币定先庄，逐回合轮换；庄家自动 S17（"喘息回合"）。AI 始终以最优决策应战，**不随难度变化**（口径见 contest-rules §3）。
- **道具卡**：计入 hit（抽到道具卡或扑克后均可随时停牌）；牌靴在局内跨回合持续；权重公式在道具侧有剩余且未达抽取上限时保持目标道具概率恒定（扩卡不漂移；边界情形退化为必抽扑克）；"用后是否回到牌堆"是每张卡的固有消耗性属性。经典元素迁移为卡：加倍卡（本回合分数变化 ×2）、保险卡（对手天然时本回合视为平局）、双牌组卡（追加第二副扑克）。无分牌、无投降。
- **难度**：只约束道具与赛制（卡池分级、道具概率、道具手牌容量、BO 长度）；解锁链 轻松 → 标准 → 挑战 → 危险 → 噩梦 → 自定义对局，逐级通关解锁。
- **图鉴**：随时可看，遭遇即解锁，成就式弹窗 + 未查看感叹角标 + 自动滚动到最前未查看行。
- **存档**：全新独立系统，只记录难度解锁与图鉴解锁/查看状态；无战绩、无历史对局；中断或刷新 = 放弃当前比赛（roguelike 语义）。
- **版本**：竞赛模式线从 **0.2.0** 起跳。

## 流程

新需求先登记到 GitHub Issue 或 `requirements/active/REQ-*.md`，再在本路线图关联排期，不在 PRD 内写需求正文。落地后回写对应 `design/` 快照，按需求索引流程归档；发布后更新本表状态。未来存在同主题 GitHub Issue 时按 Issue 优先原则对齐。

版本迭代：自 v0.1.0（2026-09-22 首次发布）起，每次发布自动递增版本号，需求随所属发布迭代版本；仅当某一需求被标记重大升级时，由用户指定版本号跳跃。**竞赛模式线从 v0.2.0 起跳**：竞赛开发期间，经典模式的修复照常以 v0.1.x 递增发布；竞赛线内部迭代走 v0.2.x；0.x 语义下不占用 1.0.0，1.0.0 留待产品形态稳定后另行裁定。

v0.1.1（2026-09-22）为发布后紧急热修复（双击 `file://` 白屏，见 [ADR-002](./adr/ADR-002-singlefile-release-build.md)），只改构建产物形态，不改规则与存档。

v0.1.2（2026-09-22）：[REQ-2026-007](./requirements/archive/REQ-2026-007-about-panel.md) 设置内关于页完成开发与验收并归档，展示构建版本、仓库、MIT 许可与反馈入口。发布版本从 package.json 注入，随每次发布自动同步。
