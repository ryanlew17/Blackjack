## REQ-015 已实现范围（2026-10-20）

`src/domain/contest/engine/` 提供纯 TypeScript 的单回合引擎，未接入生产入口。`createRound(firstPlayer, random, rules?)` 返回权威状态和四次发牌事件：按先手／后手交替各发两张，双方第一张仅自己可见。先手由后续 Match 生命周期传入；本项不决定开场硬币或跨回合轮换。随机源仅在 11 张牌洗牌时消费 10 次，后续抽牌按权威牌堆顺序进行，空堆不重洗。

`transition(state, { type: "Hit" | "Stay", player })` 与 `legalActions(observation)` 使用状态携带的冻结规则快照。初始目标默认 21，可注入其他正安全整数目标作为后续效果边界。每次 Hit／Stay 只换人一次；达到目标或爆牌仍可行动。两次连续安静 Stay 后，事件顺序为第二次 stay → 先手 reveal → 后手 reveal → settled；结果只在最后一个快照出现，重复或非法命令返回原状态引用、零事件。`dealing`／`revealing` 是不可行动的回放阶段，终态为 acting 或 settled。

`observeRound`、`projectRoundEvent`／`projectRoundTransition` 同时过滤载荷和每个事件快照；只保留自己的数字牌、对手明牌和剩余牌数，不给出对手完整点数／爆牌或牌堆身份与顺序。自己未公开的首张牌带 `faceDown: true` 且有值，对手对应值为 null；`visibleTotal` 仅含公开牌，存在未知牌时 `total` 为 null。合法性只使用行动方、阶段和牌堆张数，不能借此查询暗牌。状态、事件、观察深冻结。

为 REQ-019 保留 `Turn.usedTrump` 与内部 `recordTrumpConsumption` 接缝：经后续执行器验证并消费资源后才可调用，即使效果失败也重置安静记录且不换人；该 Turn 的 Stay 不计安静。尚无 PlayTrump 命令、资源或效果执行器。Match/Game 累计积分、AI、应用、UI、存储均不在本次范围。

## REQ-016 已实现范围（2026-10-20）

`createMatch(random, roundRules?)` 建立标准无道具 BO5，先赢 3 个 Game 结束；每个 Game 初始目标 5 分。MatchRules 固定 `difficulty: "standard"`、`bestOf: 5`、`gamesToWin: 3`、`trumpDealing: false`，整场冻结；同一 RoundRules 引用传入后续每个 Round。可选 RoundRules 只沿用既有牌面目标参数边界，默认 21；无其他档位、资源预设或候选卡发放。

`transitionMatch` 接收带全局 `roundNumber` 的 Hit/Stay 或 NextRound。每个已完成 Round 在同一命令中结算一次：赢家 +1，平局 +0；Game 的 `roundsPlayed` 包含平局。4:4 时目标从 5 递延到 7，6:6 时到 9；8:6 时仍须达到 9，不按领先两分提前胜局。达到目标时 Match 胜局 +1，达到三局时 Match 完成；没有外部提交回合结果或积分的命令。

Round 结束保留揭牌与比分，阶段为 round-complete 或 game-complete；NextRound 才开始下一次发牌，game-complete 时同时建立新 Game（分数归零、目标恢复 5、局内回合数归零）。全局 roundNumber 跨 Game 递增。开场只抛一次硬币，后续每次新 Round 均交替先手，包括平局与跨 Game；普通 Hit/Stay 和结算不消费随机，NextRound 仅消耗新回合的 10 次洗牌值。旧回合编号、错误行动方或不合阶段的命令原样返回，complete 阶段没有可用动作。

Round 的 stay → 先手 reveal → 后手 reveal → settled 后，依次产生 round-scored → 可选 target-extended → round-cleanup → 可选 game-won → game-cleanup → match-won。中间 resolving 快照不能行动，完整结果在 transition 返回前确定。round-cleanup 重置牌面目标和 Turn 临时记录，保留结果；game-cleanup 为后续手牌／资源清理留出执行位置。当前无道具资源或执行器，不能据此视为 REQ-019/S2 已实现。

`observeMatch` 与 Match 事件投影只暴露公开比分和 Round 观察，嵌套事件及逐事件快照均投影；`legalMatchActions` 消费该观察。规则层仍只在内存运行，不提交通关或图鉴、不写存档、不挂载 UI。跨 Match 的延迟命令取消与中断语义由 REQ-017/018 实现。

## REQ-017 已实现范围（2026-10-20）

`application/contest/controller.ts` 提供开始／重开／退出、命令、投影回放、跳过动画、暂停／恢复与窄策略端口，useContest 负责 React 订阅、读取共享设置、音效与可见性／卸载处理。权威 Match 只在协调器内部，命令先提交完整终态，再回放投影事件；公共 match 是展示帧，snapshot() 是权威 human 观察，二者均无隐藏牌堆信息。快速重复动作在 busy／paused 期间被拒绝。

队列结束后读取权威行动方；只有 AI 的合法 Turn 才延迟 300ms 请求一次 Hit/Stay。占位策略在应用层，输入 ai 观察及合法动作，自身总和 <17 且允许 Hit 则 Hit，否则 Stay；不传真实随机源、不搜索或主动用卡。待执行回放和策略任务有取消代次，退出／重开／暂停使旧回调失效；回到可见时跳到已提交终态。玩家和策略都不从动画中计算积分。

useContest 只读既有 API 提供的设置，不更新经典进度或设置信封；无对局／元进度写入。经典协调流程未改，生产入口仍未接竞赛。控制器的真实引擎测试与 hook 服务端初始化已验证；客户端和界面冒烟随 REQ-018，PlayTrump 实际联动随 REQ-019，正式无道具 AI 接口收敛仍为 REQ-020。

## REQ-018 已实现范围（2026-10-20，用户页面测试通过并归档）

首页提供经典与固定标准无道具 BO5。竞赛页只读 useContest 的展示观察，显示胜局／积分／递延目标、双方数字牌、剩余牌数与行动方；自己的暗牌可见，对手暗牌在引擎揭牌事件前没有数值 DOM。Hit／Stay／继续／重开均经应用 API；规则和结果不在组件中计算。

## REQ-019 已实现范围（2026-10-20）

已有 transition／transitionMatch 新增 PlayTrump，真实命令原子消费实例、执行效果及触发的留场替换，仍先提交终态再回放。RoundRules.trumps 为可选公开定义与五格桌面容量，createMatch 的第三参数 TrumpSetup 是显式注入的私有固定每局资源；Match 内复制冻结并复用规则快照，私有初始手牌模板不进入观察／事件。默认规则仍无该字段、trumpDealing 为 false，正常无道具比赛与占位策略行为不变。

`engine/effectTypes.ts`／`effects.ts` 只提供已验证的有限原语：指定数字抽取（失败也消费，不重洗）、收回最后一张明牌（追加回牌堆末尾，首张暗牌不可退）、清除一个对方留场实例；可选 table.pointTarget 支持全局互斥目标及清除后恢复规则基准（标准为 21）。命令前只依据公开条件及自身手牌校验：不查询指定数字是否实际在牌堆；混合卡先验证桌面容量与目标，再消费／抽牌；替换自己旧目标可释放一个己方位置，不能用对方位置抵扣己方五格。一个最小命令仅携带一个清除目标，多目标与任意效果组合仍待 S2 明确。

每次合法消费先记录 usedTrump 并清零 quietStays，效果抽牌不等于 Hit，整个 Turn 可连续用卡；Hit／Stay 才换人。消费方的 Stay 不计安静，之后需两次安静 Stay 才揭牌结算。Round 清理全部留场并重置目标／临时记录，保留未用手牌；Game 清理手牌、桌面与弃置实例，下一局按该场私有模板重新建立固定资源。重复清理不重复回收；没有补给池、掉落或触发补牌。

事件为 trump（played／draw／return／removed／placed）及逐事件快照，消耗的混合实例先暂存弃置区，再转入桌面，保证每个展示帧中实例不重不漏。公开观察只含自己的道具实例、对方数量、公开桌面／弃置；牌堆、对手暗牌及未使用道具身份仍被过滤。指定抽取失败的 card 为 null，不通过合法按钮提前泄露可用性。移除留场不撤销已完成的抽牌。

`engine/prototype.ts` 的七个 test-* 定义仅供固定夹具：Draw 2、Return、Target 17／24、Dispel、Draw 3 + Target 24 混合卡及五格测试用无效果 marker。marker 不代表新增正式玩法；全部不从 index 再导出，生产入口守卫排除 prototype，21 张候选仍全部不可玩，F1/P0 不接入。应用协调器的双方受控端口验证真实命令与回放，生产 controller 继续仅对玩家开放 Hit／Stay／NextRound，没有测试页面或运行时开关。

S2 待定：正式卡池、掉落／资源回收、任意组合／触发链、交换与计分道具、手牌上限、图鉴／元进度及组合 AI。本项证明有限命令／事件／投影／清理接口，不把测试资源策略当成正式配置。

## 1. 术语与设计依据

| 层级   | 中文     | 英文  | 含义                                               |
| ------ | -------- | ----- | -------------------------------------------------- |
| 场     | 大比分   | Match | BO-N，先赢多数局获胜，也是难度通关单位             |
| 局     | 小比分   | Game  | 回合积分累计到当前胜局目标分，获胜后大比分 +1      |
| 回合   | 一次对弈 | Round | 发牌、双方交替行动、揭牌与一次积分结算             |
| 行动轮 | 一方行动 | Turn  | 当前玩家连续用卡后选择要牌或停牌，将行动权交给对手 |

模式英文名为 **Contest Mode**。文档中的“牌面目标点数”指默认 21、可被道具改变的比较目标；“胜局目标分”指初始 5、平分时递延的积分门槛，两者独立。

以下三种口径须区分：

- **原版玩法依据**：唯一数字牌、交替行动、连续用卡、停牌后重决策、可挽救爆牌、即效与留场效果。来源见 §11；资料为游戏内说明转录及攻略交叉核对，不代表取得原版源码或精确掉落权重。
- **本项目改编**：积分制 BO-N、目标递延、难度解锁与图鉴、仅保存元进度；不复制剧情敌人的专属权限或脚本。
- **待验证设计**：完整卡池、获取分布、持牌容量、积分道具映射与搜索预算，按 §10 定稿。旧版固定概率公式不再是实现约束。

## 2. 赛制与计分

- 场赛制沿用：轻松 BO3（先赢 2 局），标准与挑战 BO5（3 局），危险 BO7（4 局），噩梦 BO9（5 局）。BO-N 是最多打 N 局、先赢多数局，不是必须打满 N 局。
- 胜局目标分初始为 5。当双方同分到达“当前目标分 − 1”（4:4、6:6、8:8…），先将目标分 +2；达到当前目标分的一方赢得该局。这是**目标递延制**，不是无条件领先两分制。
- 无计分道具时，回合赢家 +1，输家 +0，平局双方 +0。平局也是已完成的 Round，仍推进回合计数与先手轮换；无赔率与天然 Blackjack 优先级。
- 积分道具的方向、叠加、最低/最高得分和结算顺序在 S2 定稿。原版提高对手输牌代价、降低自身输牌代价的效果不能直接等同于双方胜者得分 ×2。
- 若采用 +2 等跳分方案，仍遵守既定目标递延语义：3:4→5:4 可直接胜局，不补造中间的 4:4。此例是计分规则边界，**不是承诺首批存在加倍卡**。
- 每次 Round 只结算一次。先比较最终牌面，再按已定稿的积分修正得出该回合积分，随后检查目标递延、局胜与场胜；道具使用过程中不提前颁发积分或通关。
- 局结束清空双方道具手牌及留场效果，重置本局道具资源配置；下一局的先手轮换延续，不重新抛硬币。场胜后更新难度通关元进度。

## 3. 数字牌与行动流程

### 3.1 数字牌与信息

- 每个 Round 使用双方共享的 **1–11 各一张**数字牌堆。1 始终计 1，11 始终计 11；无花色、A 软硬转换或十点人物牌。
- 双方各发两张，第一张仅自己可见，其余数字牌公开。自己暗牌属于自身已知信息，对手暗牌不进入玩家/AI 观察视图。
- 每回合重新构建完整数字牌堆；回合内退牌返回当前数字牌堆，交换只改变归属，不复制或销毁数字牌。不沿用经典跨回合 52 张牌靴或“空堆即重洗”。
- 所有数字牌恰好分布于双方手牌与未发牌堆，不重不漏。指定抽取失败可以提供信息，但 `legalActions`、按钮禁用状态与未投影的事件快照不能提前暴露对手暗牌或真实牌堆顺序。

### 3.2 行动权与结束条件

- Match 开始抛硬币决定首个 Round 的先手，以后逐 Round 轮换（包括平局，跨 Game 延续）。双方都主动决策，无庄家/闲家身份或 S17 自动补牌。
- 在自己的 Turn，可以使用零到多张道具。**使用一张道具不交出行动权**，没有每 Turn 或每 Round 只能用一张的限制；持有资源、使用条件、桌面容量和封锁效果决定是否还能继续使用。
- `PlayTrump` 完成后仍轮到同一方，可接着用卡；`Hit` 正常抽一张数字牌并处理该次抽牌触发，然后结束 Turn；`Stay` 结束 Turn。道具效果中的抽牌不等于执行普通 `Hit`，不因抽牌效果自动换人。
- `Stay` 只暂时结束行动，不给玩家写入永久 `stood` 标志。对手要牌或用卡后，前一方再次获得决策机会，牌面未改变也可能需要对新的积分或资源效果作出回应。
- 结算条件为**双方连续完成未用道具、未要牌的停牌**。实现约定：成功要牌或道具被消费（即使其效果未成功）重置安静停牌记录；用过道具的 Turn 最后选择 Stay 不计为安静停牌；连续两次安静 Stay 才揭牌结算。非法命令原样返回、零事件，不推进记录或随机源。
- 例：A 用退牌→用指定抽牌→Stay，B Stay，此时不结算；A 再次行动可用卡、要牌或 Stay。若 A 也安静 Stay，才结束该 Round。
- 达到目标或爆牌不自动结束 Round。数字牌堆为空或普通要牌被封锁时，仍允许合法道具与 Stay；退牌或解除封锁后重新计算可用行动。
- 应用层处理每个命令的动画与输入锁；解锁后若仍是同一方 Turn，恢复其用卡/要牌/停牌决策，不能因一张卡播完动画而换人。

### 3.3 牌面判胜

牌面目标点数默认 21。目标变更后按新目标重新计算双方状态，爆牌是派生结果，不是不可逆失败标志。

| 最终状态         | 结论                         |
| ---------------- | ---------------------------- |
| 双方都未超过目标 | 总点数较大者胜               |
| 仅一方超过目标   | 未超过的一方胜               |
| 双方都超过目标   | 更接近目标、即总点数较小者胜 |
| 双方总点数相同   | 平局                         |

例如默认目标下 22 胜 25；己方 24 可通过退牌恢复，也可被 Go for 24 变为有效牌面。两张数字牌得到 21 只是普通 21，不提前结算。竞赛无经典下注、保险、分牌、加倍下注或投降动作。

## 4. 道具获取、区域与效果

### 4.1 获取与使用时机

- 数字牌堆与道具资源分离。普通 Hit 一定处理数字牌抽取；符合配置的触发可以另外发放道具，道具不替代这张数字牌。
- 原版参考渠道为回合开始发放、抽数字牌时可能额外获得、道具效果补充。回合开始双方各获得一张是普通基线；是否增加 Game 初始资源、哪些抽牌事件可触发额外奖励及其分布由 S2 配置定稿。S1 无道具检查点显式关闭发放，不冒充完整竞赛玩法。
- 获得的道具先进入手牌区，**即效指使用时立即生效**，不指抽到时自动发动。手牌可跨 Round 保留，到 Game 结束清空。
- 道具数据至少区分定义 ID、实例 ID、持有者和所在区域（手牌/桌面/已消费资源）；图鉴使用稳定定义 ID。若采用可回收资源池，手持/留场实例不能同时被抽到。
- 获取模型不预设固定张数全部入堆、有放回或无放回；各实验预设明确库存、耗尽与回收规则。取消旧 `p/(1−p)` 混合牌靴公式、10%–22% 概率表、每人每 Round 抽两张与 1/2/2/3/3 容量初值。

### 4.2 效果生命周期

卡牌定义须支持**使用时效果**与**留场效果**同时存在，不能只有互斥的“即效/手牌”标签。

| 内容           | 必须明确的语义                                       |
| -------------- | ---------------------------------------------------- |
| 使用条件与目标 | 自身/对手、最后一张明牌/留场道具、合法失败是否仍消费 |
| 使用时效果     | 按定义顺序立即执行，如抽牌、退牌、交换、补充资源     |
| 留场效果       | 生命周期、影响对象、叠加或互斥、被清除时如何失效     |
| 消费与离场     | 使用后去向、留场被清除后的去向、回合/局清理          |
| 触发效果       | 触发事件、顺序、可否触发自身、链条终止规则           |

- 各方桌面最多五张留场道具；桌面满时仍可用纯即效道具。混合卡需要留场容量，验证通过后才执行使用时部分，不能先抽牌再发现无位置。
- 指定数字抽取只在该数字仍在牌堆时成功；可合法消费后失败。退牌与交换针对最后一张明牌，不作用于暗牌；前置条件与失败消费语义须逐卡说明。
- Go for 系列共享互斥的目标类别：新目标牌替换旧目标牌，任一时刻只有一个当前目标。被替换的旧牌离场；清除当前目标牌后恢复默认 21，不恢复已离场的旧目标。
- 清除留场道具使其持续效果失效，不回滚已执行的抽牌、退牌或资源补充。混合牌的使用时与留场部分分别记录事件。
- 正常 Round 结束清理全部留场效果、牌面目标与触发记录，道具手牌保留；Game 结束再清空手牌及本局资源。资源回收不是“始终在牌堆内”。
- 任一道具命令及其触发链在 `transition` 内完成全部权威计算，事件按效果顺序给出快照。链条结束规则是卡池准入条件；AI 的搜索预算不能充当玩家的隐藏用卡上限。

### 4.3 首批验证范围与旧方案处置

S1 用固定夹具建立最小对抗原型，S2 再定稿并交付首批卡池：优先验证指定抽牌、退牌、交换、目标变更、清除留场效果与至少一种混合效果，必须覆盖连续用卡产生的联动。

有限效果原语按这些用例收敛，可包括 `drawNumber`、`returnLastFaceUp`、`swapLastFaceUp`、`setPointTarget`、`removeTableEffect`、`grantTrump`、`modifyScoreStake`、`restrictAction`；本表不是提前冻结的最终类型联合。定义放 domain，名称与描述进入 i18n 的 en/zh-CN 双字典。

- 原保险卡依赖天然 Blackjack、双牌组卡破坏唯一数字牌体系，退出当前基线；若重新引入须独立登记规则变更，不能自动继承旧迁移承诺。
- 加倍、攻击与防御计分均为待选映射；S2 明确方向、叠加、积分上下限与赛点案例后才进入实现卡池。
- 大量补充资源、循环补牌、长期行动封锁与大额计分效果须通过连锁终止、可反制性和对局时长评估；原版存在不等于适合短积分比赛。首批卡池不以复刻全目录为完成条件。

## 5. AI 决策

排期（2026-10-18 用户裁定；REQ-020 已实现 S1 无道具基线）：AI 需求分别放在 S1、S2 的最后实施，见 [S1 拆分](../roadmap.md)。前置开发采用最简经典式占位：自身数字总和 <17 且允许 Hit 则 Hit，否则 Stay，永不主动 PlayTrump；不复用经典牌组／A 点数／庄家强制流程。S1 末项 REQ-020 固化此无道具基线及观察接口，S2 前段继续使用它。下列推断、动态评价与多卡搜索是 **S2 末项的目标**，不是 S1 或占位阶段已实现的行为。多卡原型中的双方出牌由确定性夹具提交，不要求 AI 提前会用卡。

AI 与玩家使用相同的竞赛 `transition` 与 `legalActions`。所有难度保持同一策略与搜索预算；难度通过赛制和公开资源预设调整，不通过透视或暗改抽牌制造强度。

1. **观察视图**：包含自身数字/道具手牌、公开数字牌与留场效果、公开资源数量、积分和已发生事件；不包含对手暗牌、未公开道具身份或真实牌堆顺序。基于已知牌与公开失败结果维护可能状态分布，不把猜测当确定事实。
2. **行动生成**：动态生成用卡及目标、Hit、Stay。策略只根据可见条件生成候选；真实效果内部可查询牌堆，例如指定抽牌或最佳抽牌，但不能把隐藏查询结果泄露给策略。
3. **评价**：综合本回合预期积分、赢下当前 Game/Match 的机会、对手反制和跨回合保留资源的价值。爆牌挽救、降低失分等是场景评价因素，不是固定“先救牌再攻击”的硬顺序。
4. **有限组合搜索**：把“用卡→用卡→Hit/Stay”纳入候选，搜索对手合理回应及不确定抽牌。按节点/深度预算与相同状态复用控制耗时，预算到期使用动态启发式结果；算法、权重与预算在 S2/S3 用反例和模拟评估，不承诺全局最优。
5. **近似等价选择**：仅在价值接近的候选间引入可复现随机。卡牌分类或 `priority` 提示最多用于搜索排序/剪枝，不能直接决定最终出牌。

真实发牌/资源随机源与搜索采样随机源分离；改变搜索预算或候选顺序不能改变实际后续抽牌。测试注入固定牌堆、资源序列与搜索种子。完整状态只供规则引擎执行，AI 和 UI 均消费投影后的视图。

## 6. 难度与解锁链

| 难度 | 场赛制 | 卡池方向               |
| ---- | ------ | ---------------------- |
| 轻松 | BO3    | 基础池                 |
| 标准 | BO5    | 基础池                 |
| 挑战 | BO5    | 基础 + 进阶            |
| 危险 | BO7    | 基础 + 进阶            |
| 噩梦 | BO9    | 全量已通过准入验证的池 |

- 解锁链保持轻松 → 标准 → 挑战 → 危险 → 噩梦 → 自定义对局；赢下一场比赛即完成该难度，失败可重试。
- S3 决定各档获取分布、持牌容量、双方资源分配与卡池细目，不承诺随着难度单调增大道具概率。原版持牌容量等数值可作为实验参考，不自动成为本项目限制。
- 每个 Match 开始冻结规则/卡池/资源预设，途中不因调参、设置修改或解锁新图鉴而变动。AI 策略保持一致，预设差异须可说明、可复现。

## 7. 图鉴与自定义对局

- 图鉴随时可查看，遭遇即解锁：自己获得可见道具，或观察到对手公开使用/作用，更新定义 ID 对应条目。对手获得未公开道具不触发能泄露身份的图鉴提示。
- 保留未解锁（???）、已解锁未查看（感叹角标）、已查看三态；新解锁提示，打开时自动滚动到最靠前的未查看卡。
- 通关噩梦后解锁自定义对局；仅可勾选已解锁卡，自定义比赛不解锁新图鉴。所选卡池对整个比赛的双方生效，不从未选卡中生成隐藏对手道具。
- 卡池依赖校验、缺少反制卡的组合及其余自定义项随 S5 定稿；非法配置在开局前提示，不能静默补入未勾选或未解锁卡。

## 8. 中断、恢复与存档边界

- 竞赛对局只存在于内存。返回首页需确认放弃；刷新即放弃当前 Match，无对局恢复、战绩或历史存档。经典模式的暂停与自动恢复保持现状。
- 元进度只记录难度通关与图鉴解锁/查看，详见 [contest-save-format.md](../contracts/contest-save-format.md)。对局结束前已发生的公开遭遇可提交图鉴进度；难度通关只在权威 Match 结果确定后提交。
- 独立的是游戏状态、存储键与校验契约；语言、音量等应用设置仍按现有经典信封共享，不宣称所有数据互不可见。元进度冲突处理不恢复或覆盖内存竞赛牌面。

## 9. 架构与界面落点

- 独立竞赛状态机、数字牌/道具资源模块、效果解析和 AI；最小基础设施复用边界见 [ADR-004](../adr/ADR-004-contest-turns-and-shared-boundaries.md)，其取代 [ADR-003](../adr/ADR-003-contest-mode-engine.md) 中不适用的共享与牌靴假设。
- 经典 CardId、A 点数计算、创建 52 张牌堆的包装、下注/存档验证与经典固定牌序助手留在 classic。通用数组洗牌、随机注入与事件调度只在确有两个消费者时提取。
- 每个命令先提交权威内存终态；需要更新元进度时再按存档策略写入，随后播放投影后的事件。存储失败提示不回滚已完成对弈，动画回调不计算牌面结果、积分或通关。
- 规则在 Match 内冻结，`transition` 与 `legalActions` 使用同一规则快照；不在经典 `RuleSet` 中增加 mode 分支。
- 首页 → 模式选择 → 竞赛难度选择（S3 起；S1–S2 固定标准难度）。竞赛界面展示大/小比分、当前牌面目标、当前行动方、道具手牌与留场区；不得复用“庄家自动补牌”提示。
