## 1. 组件结构

```text
src/presentation/

  shell/ModeSelect.tsx           # 首页入口
```

## 2. 多手牌局与保险界面

- GameTable 同时展示两手，标注当前手、逐手下注、状态与结果；保险阶段与玩家回合均隐藏庄家暗牌。
- ControlDeck 在保险阶段显示固定保费、净赔说明、购买/放弃按钮及余额不足提示；其余玩家动作来自 legalActions。保险结果独立展示。
- HistoryPanel 每局一条，包含每手下注/结果/净收益、保险明细及整局总净收益。mixed 不覆盖逐手输赢。
- 规则面板与中英文结果文案覆盖保险、投降与旧档版本提示。按钮通过原生 Tab/Enter/Space 操作；不新增自定义快捷键。
- 玩家动作按钮区下方有动作提示行：仅当对应动作可用时显示（优先级 分牌 > 加倍 > 投降，同一时刻至多一条），文案复用 i18n 现有 helpSplit / helpDouble / helpSurrender；提示行预留固定高度，出现/消失不移位按钮行，不含可聚焦元素、不参与 Tab 序。桌面端按钮的 `title` 悬浮说明保留为 hover 增强。
- 牌桌增高以容纳状态标签；移动端双列手牌与可换行操作按钮，320px 中英文无横向溢出。

## 3. 硬约定

- **i18n**：所有用户可见字符串必须加入 `i18n.ts` 的英文与中文**两个字典**，禁止硬编码文案；默认语言取浏览器，手动选择持久化。
- **面板关闭统一走 `closePanel()`**（同时清空导入待确认快照），不得直接 `setPanel(null)`。
- **样式集中在 `styles.css`**，无 CSS 框架；布局必须保证 **320px 宽度无横向溢出**，桌面与移动视口均需验收。
- **样式补丁只留最终值**：同一属性的响应式补丁只保留最终生效值，禁止叠加旧值；每个断点单一媒体块，且媒体查询覆盖必须排在被覆盖的基础规则之后（同特异性按源序生效，源序颠倒会静默丢失覆盖——REQ-2026-009 实测教训）。
- **`.table-meta` 的 `z-index: 1` 不得移除**：`.dealer-zone` 是 `top: 30px` 的绝对定位层，缺少该层级会遮挡历史按钮使其无法点击（2026-09-22 浏览器实测确认的存量修复，无视觉变化）。
- 动效：遵循系统/用户减少动态效果设置（设置项 `motion`）；动画只读事件快照，不回写状态（见 `state-and-animation.md`）。
- 音效：Web Audio 合成，首次用户交互时 `unlockAudio()` 解锁；遵循静音与音量设置，无音频资源文件。
- 键盘操作：按钮使用原生 Tab/Enter/Space；弹层 Esc 关闭、焦点限制在弹层内。品牌区为非交互元素（`div`，无 href/onClick/aria-label），首页 Tab 首停为静音开关；牌桌页首停为顶栏规则（≤760px 隐藏后首停为静音开关）。切换模式时焦点移到新页标题，牌桌内均有「返回首页」按钮。

## 4. 设置与关于

设置内的「关于」按钮可由 Tab 聚焦并 Enter / Space 激活，在同一 Modal 内切换到关于视图，标题同步更新。关于页将焦点移至「返回设置」按钮；返回设置后焦点对称地落回「关于」入口按钮（Enter 可再次进入），关闭再打开也回到设置首页。Esc、关闭按钮和背景关闭均由 App 的 `closePanel()` 处理。

存档面板在存档版本不受支持（version）或内容损坏（corrupt）时不显示导出按钮与存档摘要——该状态下内存快照是全新占位档，导出会误导玩家覆盖真实备份；导入入口保持可用。存储不可用（storage）时导出保留，作为设计上的逃生通道。

关于页显示 package.json 的当前发布版本（Vite 构建时注入 `__APP_VERSION__`）、项目仓库、MIT 许可与 GitHub Issues 反馈说明。三个外部链接均新标签页打开且设置 `rel="noopener"`。文案完整进入双语字典，长仓库地址允许换行，320px 无横向溢出；无网络版本探测或遥测。

## REQ-018 模式入口与无道具竞赛（2026-10-20，用户页面测试通过并归档）

App 持有不落盘的 home/classic/contest 模式，首次访问与刷新均进入首页。useGame 始终保留经典权威状态和设置信封；进入经典复用原组件、存档、历史与规则。设置／音效／关于共用；首页设置不提供重开，竞赛设置的「新比赛」只重开竞赛。

进入竞赛通过useContest.start新开固定标准含道具BO5；难度／图鉴／自定义／主动技入口仍未接入。ContestTable只读MatchObservation，显示胜局、积分、目标、数字牌、剩余数与行动方，手牌及留场见道具章节。NumberCard收到null只生成牌背与暗牌名称，本人未公开首牌标记仅自己可见；结果读取winner，不在组件判胜或计分。

Hit／Stay／继续按钮只采用应用 actions、busy 与 paused；回合和局结束后手动继续，场结束后可新开或返回首页。打开竞赛弹层先 pause，关闭统一 closePanel 并 resume；返回首页和中途重开需确认，取消／Esc／背景关闭继续原比赛，确认离场调用 exit 取消旧队列和对手任务。已结束比赛可直接返回首页；场结束页且没有弹层时的新比赛直接 restart，不弹放弃确认。设置弹层中的新比赛仍走确认，这一豁免不扩展到中途重开。刷新丢弃比赛，不恢复竞赛牌面，不写竞赛存档。

竞赛数字牌采用可换行布局；所有新增文案进入两字典，按钮均为原生可聚焦控件。Motion 与协调器共同遵守用户／系统减少动态设置；共享 useSystemReducedMotion 使用 matchMedia 订阅系统偏好实时变化，不依赖 Motion 只读初始偏好的钩子。验证证据留在对应REQ；短视口、经典暗牌隐藏与行动反馈约束见下节。

## REQ-019 页面体验修整（2026-10-20）

竞赛页使用紧凑顶栏、比分和牌桌留白，行动方在各手标题行并显式行高；竞赛与经典All-in等主操作保持49px。常规2–3张牌在784×803／320×900可见状态与Hit／Stay；长手牌自然扩展并滚动，无吸底遮挡焦点／弹层，不改变经典牌桌尺寸。

ContestStatus 新增双语「正在回放行动」状态，发牌、思考、行动回放与揭牌不混称；输入锁的透明度不做渐变，正常思考与事件等待时间保持原值。设置／规则／返回确认仍暂停、关闭恢复，生产界面已接道具入口；主动技交互仍待实现。

经典 Card 在 hidden 时不挂载正面或任何牌面值属性，只保留统一背面；初次渲染即面向牌背，合法揭牌后才挂载正面并沿用翻牌动画，减少动态直接切换。此改动只作用于表现层，未改经典规则、存档、资金或 useGame。发牌／恢复时隐藏状态与授权揭示保持一致，实际验证证据归对应REQ。

## S2追加交互设计（道具界面见REQ-026快照，技能待REQ-027实施）

[REQ-026](../requirements/archive/REQ-2026-026-contest-trump-interface.md)接道具抽取／生成／删除／转移、出卡销毁与独立留场效果反馈，先准入53卡；[REQ-027](../requirements/active/REQ-2026-027-contest-active-skills.md)再补回仙第54卡和15主动技。道具界面已在下节实现；以下技能交互仍是027计划。

进入比赛前先自选本档可用技能、确认后才建立Match和随机AI技能；S2固定标准，S3在前面加难度选择。双方技能身份公开，自己的球形发动按钮在独立区域，不能塞进Hit／Stay行；显示准确本人剩余次数／局内资格，条件和反馈由观察提供。对方隐身布置与真实次数变化不进DOM或公共提示，未知次数用已知范围／未公开状态表达。

双生花在对方Turn稳定命令边界提供发动／放行入口，不能靠抢点动画间隙；选择取消、Esc、面板暂停、旧窗口恢复按既有协调机制失效，不自动提交。球形按钮仍为原生可聚焦按钮，Tab／Enter／Space、中英、减少动态、784×803／320×900和短视口主操作可达均需实际浏览器证据。

S4图鉴单开主动技页／页签，介绍技能条件和五档场次数；不套用道具“遭遇未知身份”的三态，也不把技能ID写入道具图鉴字段。主动技专用页面／按钮尚未实现，按REQ-027及S4边界接入。

## REQ-026 道具界面（2026-10-23，外部浏览器审查与复核通过）

首页竞赛入口显式使用S2标准BO5含道具预设；卡池仍为025准入的53定义，标准库存61，回仙／技能待027。首页、规则、比分与结果说明同步双语；对手仍用确定Hit／Stay基线，未提前接组合AI。

主操作后有默认收拢的本人道具与双方留场区。本人手牌可查看效果和使用条件；对手仅显示数量／库存计数。原生dialog中按应用trumpCommands显示合法明牌／留场目标、己方交换目标、费用勾选与公开目录声明；点击使用才提交，不加第二层确认。非法卡可读条件，使用按钮禁用；指定抽取与截流不预告隐藏成功。悔牌因公开Turn边界关闭时显示专门原因，不读取逆操作差量。

取消／Esc不消费，原生dialog恢复焦点；成功用卡或输入代次改变关闭旧选择，必要时焦点退至手牌summary。回放结束仍按权威行动方决定是否继续用卡。道具区位于49px主操作之后，展开允许自然滚动，不设置固定底栏。规则／设置／离场确认仍由App暂停和恢复。

留场显示控制方、压制状态、绑定对象、原到期玩家＋Turn、触发余量与从众记录；移花不改变压制绑定或到期。当前窥序只来自round.peek，失效后不在历史反馈重放数值；共生仅显示待结算提示，公开倍率不暴露未知暗牌贡献。有效总点数／目标直接读取观察。

反馈保留最多48条授权事件，只描述已发生的抽取／生成／删除／转移、零领取、放置／清理和悔牌窗口关闭；对方null身份不误报失败。round-scored的基础分、攻防、封顶、护身／息战与各来源在清理后仍可查看；组件不算积分或胜负。悔牌反馈当前不点名撤销对象，实际验证与未覆盖边界归REQ-026。
