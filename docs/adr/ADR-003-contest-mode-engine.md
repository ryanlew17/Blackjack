# ADR-003: 竞赛模式独立引擎——domain 三库结构与独立存档

日期：2026-09-23
状态：已采纳（S0 文档基线；实现随 S1 落地）

## 背景

竞赛模式（积分制 BO-N 对弈 + 道具卡，roadmap S0–S5）与经典模式共享 21 点的基本牌张语义，但状态机差异是根本性的：无下注阶段、以积分替代金额（经典引擎的金额校验语义整体不适用）、牌靴混入道具卡并按权重抽取、场/局/回合三层结构、对局不持久化（只存解锁元进度）。ADR-001 的 rules 参数化面向**同一状态机内**的桌规变体（软 17、赔率），不适合承载一个不同构的玩法模式。

## 决策

- `src/domain/` 重组为三库：
  - `shared/`：两模式共用原语——CardId、点数计算（score）、洗牌与随机注入、事件快照模式、固定牌序测试助手；只放双方都用或明确可复用的最小集合。
  - `classic/`：现 `game.ts` 及其测试整体平移，行为与测试零改动。
  - `contest/`：竞赛模式独立状态机（场/局/手）、权重牌靴、AI 闲家策略与用卡启发式、卡牌目录。
- 竞赛模式拥有独立的 `transition`/`legalActions` 入口与事件类型；**不经由**经典 `transition` 的 rules 参数分支实现。
- 竞赛存档为全新独立系统：独立存储键与独立契约（`contracts/contest-save-format.md`），只存难度解锁与图鉴状态；经典存档（键 `green-room.blackjack.v1`、格式 v2）一字不动，不做搬迁。

## 理由

- 备选「扩展经典 `transition` 增加 mode 分支」被否决：金额校验与积分语义互斥、52 张覆盖校验与道具牌靴互斥，分支会让"经典模式零回归"承诺不可维持，存档校验矩阵爆炸。
- 备选「竞赛逻辑放 application/UI 层」违反硬约束「UI 不绕过规则引擎计算结果」。
- 三库结构让竞赛引擎可自由演化（道具卡、权重公式、效果原语）而不传染经典；shared 边界倒逼复用抽象保持最小。

## 后果

- 正面：经典引擎与测试原样平移即可全量回归；两模式可独立发版（经典修复走 0.1.x，竞赛线走 0.2.x）；共用原语被两个消费者约束，抽象质量有天然检验。
- 代价：S1 需一次目录重组（import 路径调整，用 git mv 保留历史）；`application/useGame` 中的动画队列、存储生命周期、跨标签冲突检测需抽为共享基建，两模式各挂薄封装；presentation 新增首页模式路由。
- "先提交后渲染"硬约束对竞赛引擎同样适用：道具卡效果全部在竞赛 `transition` 内一次性结算，动画队列只播事件快照，动画回调永不决定积分。
