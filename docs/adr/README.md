## 维护方式

每条ADR围绕一个实质决策，包含背景、决定、理由／备选和后果。保留决策时的必要背景；按主题原位修正适用范围和失效描述，当前代码结构见[架构](../architecture.md)。

真正推翻既有决定时新增编号，明确supersede关系，并更新旧记录状态与索引；“新增决策”不等于在现有ADR末尾追加每个REQ的实施、排期或验收。实现符合既有决策时只维护相关主题，不增加进展章节。
