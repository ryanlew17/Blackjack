# ADR-004: 竞赛回合制、最小共享边界与 AI 信息隔离

日期：2026-10-04
状态：已采纳（设计基线；实现随 S1–S5 落地）
取代范围：[ADR-003](./ADR-003-contest-mode-engine.md) 中共享扑克 CardId/score/经典测试助手、混合权重牌靴、AI 闲家基本策略和统一存储生命周期的假设；保留独立竞赛引擎、四层依赖、经典兼容与独立元进度存档的决定。

## 背景

用户确认参考《生化危机7》21 点修订竞赛玩法，并允许停牌后重决策、连续使用道具发挥联动。设计依据见 [contest-rules.md](../design/contest-rules.md) §11。竞赛采用唯一 1–11 数字牌、双方交替行动、动态目标、独立道具资源和积分赛制，与经典扑克的 A 软硬点、S17、天然及金额语义不同。

当前 `src/domain/game.ts` 的 score 使用扑克牌 ID 与 A 降点，shuffle 创建固定 52 张牌；`src/domain/testHelpers.ts` 的 fixedRandom/dealt 也绑定 52 张牌及下注发牌。它们不能只经目录平移便成为通用原语。

## 决策

### 独立规则，按消费者提取共享工具

- 继续规划 `domain/shared/`、`domain/classic/`、`domain/contest/`；本次只改文档，不移动源码。
- classic 保留现有牌 ID、点数/天然判断、52 张牌堆包装、RuleSet、金额/结算、存档校验与下注测试助手。S1 若移动文件只调整路径，现有外部规则、存档键与格式保持兼容。
- contest 拥有独立数字牌类型、Match/Game/Round/Turn 状态、判胜、积分、道具区域/获取/效果与 AI；独立 `transition` 和 `legalActions`，使用同一 Match 内冻结的竞赛规则快照，不扩展经典 transition 的 mode 分支。
- shared 只提取经两方实际使用验证的泛型数组洗牌、随机源接口等最小工具；不要为了填满目录而共享规则联合类型。牌面展示在 presentation 用适配器复用，不强迫两类牌共用一个 domain CardId。
- 事件快照形态与调度可复用，事件含义和隐藏信息投影由各引擎定义。测试可复用与牌数无关的序列工具，各模式保持自己的发牌夹具与断言。

### 一次命令与一个行动轮分开

- `PlayTrump` 及其触发链原子推进状态，但保留当前行动方；`Hit`/`Stay` 结束该 Turn。普通要牌与道具抽牌效果分开。
- 停牌记录可失效，爆牌按当前目标派生；只在满足安静停牌条件后揭牌判胜。一次动画完成不代表 Turn 或 Round 结束。
- 动画队列、命令输入锁、取消代次和 effectId 等可抽为共享 application 基建；竞赛先提交权威内存状态再播放视图快照，不能把整个 Turn 压成不允许干预的自动流程。
- 持久化生命周期保留模式适配：经典保存完整权威游戏；竞赛仅保存难度/图鉴元进度。对局内存提交不依赖 localStorage 成功，不抽出一个强迫两模式保存同类内容的 saveGame。
- 元进度读写、冲突检测可复用版本/存储工具，各键独立校验；语言/音量等设置仍按当前经典信封共享，独立存档不等于所有应用数据互不可见。

### AI 消费观察视图，动态搜索组合

- 策略入口只接收自身信息、公开事件和合法推断；规则引擎持有真实状态。隐藏数字牌、未公开道具身份和牌堆顺序不传给 AI 或 DOM。
- 动态生成合法用卡/目标、要牌与停牌，搜索有限多卡组合和合理对手回应；评价本回合积分、局/场胜率与保留资源，算法预算由 S2/S3 证据定稿。
- 卡片 priority 只可作为搜索排序提示，不作为硬决策优先级。近似等价方案可使用独立种子随机；搜索不能消费真实发牌或道具获取的随机流。
- 保持各难度同一 AI 策略与预算；资源预设形成难度差异。不承诺“始终最优”，也不声称复刻了未公开的原版 AI。

## 理由与备选

- 在经典引擎加入竞赛 mode 分支会混合扑克与数字牌、金额与积分、永久停牌与可重决策，扩大经典回归面，继续否决。
- 为复用而统一 score/CardId 会掩盖两模式真实语义；把 shuffle 拆成通用数组算法与经典创建牌堆包装才可能共享。
- 完全复制动画/随机/存储底层会重复维护，采用模式适配加最小工具复用；无需统一完整状态机或存档生命周期。
- 单张静态优先级无法处理联动、目标变更及赛点资源价值；直接追求全树最优又缺少可控预算，采用动态评价与有限搜索，并用组合反例验证。

## 后果

- S1 需同时验证经典兼容、竞赛信息投影与最小多卡原型，再冻结效果入口；仅无道具 BO5 跑通不足以证明道具框架合适。
- S2/S3 需记录卡定义、概率模型、连锁终止与 AI/平衡数据；只冻结有证据的参数，不继承旧固定概率公式或扑克迁移卡。
- 所有 domain 模块保持纯 TypeScript、随机可注入；每条命令先提交权威状态再播放事件，UI 与动画均不决定积分。
- 经典存档仍为现有键 `green-room.blackjack.v1` 与格式 v2，竞赛元进度契约仍为未实现的 v1 草案。本决策不发布新版本或修改已交付功能。
